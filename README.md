# Mellow

Mellow — Telegram-бот для приватного Minecraft-сервера: заявки с темами форума, модерация, уровни прав, счётчик сообщений, поддержка/предложения/обращения и защищённое управление whitelist через Paper-плагин.

## Состав и текущий статус

- `mellow/` — Python 3.11+ бот на aiogram 3, SQLAlchemy async и Alembic.
- `minecraft-plugin/` — Paper-плагин с локальным HTTP API, токеном, allowlist IP и ключом идемпотентности.
- `config/` — настраиваемые поля анкеты и уровни администрации.
- `tests/` — проверки privacy-фильтра и основных правил.

Приватность — принципиальное ограничение: сообщения с `sender_chat` (включая сообщения от имени группы/анонимных администраторов) исключаются из счётчика и не связываются с аккаунтами. Их текст не журналируется и не пересылается пользователям из служебных тем. Для защиты от дублей в БД фиксируется только Telegram update ID без ID автора/чата. Никакой косвенной идентификации нет. Бот не хранит содержимое сообщений групп в логе.

## Быстрый старт (Linux/VPS)

1. Создайте бота через `@BotFather`, скопируйте токен в `.env` как `BOT_TOKEN`. Включите группы и отключите privacy mode, если нужны подсчёт сообщений и русские команды в группах: `/setprivacy` → Disable. Добавьте бота в нужные супергруппы.
2. Для чата заявок и обращений включите темы (Topics) и выдайте боту право управлять темами, отправлять/редактировать сообщения, читать сообщения. Для модерации выдайте нужные права администратора в игровом Telegram-чате: ограничение/бан пользователей. ID чатов — отрицательные `-100…` значения.
3. Скопируйте `.env.example` в `.env` и укажите токены, ID чатов и Telegram ID персонала. Формат `STAFF=telegram_id:level,...`; при первом запуске список добавляет начальные роли. Уровни 1–5 и подписи/права редактируются в `config/levels.yml`. Текущие роли хранятся в БД и меняются командами владельца `назначитьадмина <ID> <уровень>` и `снятьадмина <ID>` в служебной группе; собственные права менять нельзя. Укажите `DATABASE_URL` (SQLite для одного процесса или PostgreSQL для рабочей установки).
4. Установите Python 3.11+, затем:

   ```sh
   python -m venv .venv
   . .venv/bin/activate
   pip install -e '.[test]'
   cp .env.example .env
   # заполните .env, затем примените миграции
   alembic upgrade head
   mellow
   ```

   Форма анкеты редактируется в `config/questions.yml`; изменения применяются при следующем запуске. При нескольких экземплярах бота используйте PostgreSQL.
5. Все заявки создают отдельные темы в `APPLICATIONS_CHAT_ID`. Если темы выключены или у бота нет права «Управлять темами», заявка приходит обычным сообщением в общий чат — с теми же кнопками модерации, ничего не теряется. Интерфейс не создаёт повторную активную заявку; переходы статусов выполняются атомарно. Заявка и запись о её доставке сохраняются одной транзакцией, поэтому обрыв соединения, перезапуск бота или ошибка Telegram не теряют анкету: бот сам повторяет попытку и сообщает автору, когда заявка дошла.
6. Чат должен быть форумным. Если чат поддержки/идей/обращений не задан отдельно, используются заявки/админ-чат. Укажите отдельные тематические группы при необходимости.

## Docker

```sh
cp .env.example .env
# заполните секреты и ID чатов
# заполните .env и задайте POSTGRES_PASSWORD (желательно `openssl rand -hex 32`)
# для Paper на хосте замените MINECRAFT_API_URL на приватный адрес, достижимый ИЗ bot-контейнера
docker compose up --build -d
```

В compose включён PostgreSQL, но секреты остаются только в `.env`. Перед публичным запуском замените все примеры. Не публикуйте порт Minecraft API в интернет. Важно: `127.0.0.1` внутри bot-контейнера — это сам контейнер, а не хост Minecraft. Для Docker-интеграции укажите достижимый приватный адрес Paper-хоста, привяжите плагин только к приватному интерфейсу и добавьте точный адрес/подсеть Docker-бота в IP allowlist плагина и firewall.

## systemd

Установите проект в `/opt/mellow`, положите `.env` с правами `0600`, установите зависимости и примените миграцию. Пример `mellow.service`:

```ini
[Unit]
Description=Mellow Telegram bot
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=mellow
WorkingDirectory=/opt/mellow
EnvironmentFile=/opt/mellow/.env
ExecStart=/opt/mellow/.venv/bin/mellow
Restart=on-failure
RestartSec=5
NoNewPrivileges=true
ProtectSystem=strict
ReadWritePaths=/opt/mellow

[Install]
WantedBy=multi-user.target
```

`systemctl enable --now mellow`; логи: `journalctl -u mellow -f`.

## Paper-плагин

См. [`minecraft-plugin/README.md`](minecraft-plugin/README.md). Вкратце: соберите `mvn package`, установите JAR в `plugins/`, настройте `plugins/MellowBridge/config.yml`, перезапустите Paper, укажите тот же сильный токен в `MINECRAFT_API_TOKEN`. API по умолчанию слушает только `127.0.0.1`; при раздельных хостах используйте приватную сеть/VPN, TLS reverse proxy и ограничение firewall. API аутентифицирует bearer token и принимает `Idempotency-Key`; IP allowlist настраивается в плагине.

## Русские команды модерации

В игровом чате команды вида `бан @ник [причина]`, `мут 123456789 30м причина`, `варн` и `кик` работают по username/ID или reply. Время: `30м`, `2ч`, `7д`; ограничивается максимальным сроком уровня. Поддерживаются `разбан`, `размут`, `снятьварн`, `предупреждения`. Владельцу доступны `назначитьадмина <ID> <уровень>` и `снятьадмина <ID>`; self-edit запрещён. Проверка уровня и иерархии проводится сервером и повторно выполняется при каждой операции. Бот должен иметь Telegram-права на бан/ограничение.

## Статистика сообщений

`статистика` (также `/статистика`, `/stats`) работает в личном диалоге и в группах. Участник видит свои цифры: сколько сообщений он написал в зачёт и сколько осталось до порога. Администратор любого уровня видит ещё и общую картину: всего сообщений, сколько участников в счёте, сколько выполнили порог, список участников с остатком. В группе команда понимается и без слэша, в личке для неё есть кнопка «📊 Статистика». Размер списка задаёт `STATS_TOP_LIMIT` (по умолчанию 20). Администраторы в счётчик не попадают — об этом прямо сказано в ответе бота; при `MESSAGE_REQUIREMENT_ENABLED=false` статистика сообщает, что подсчёт отключён.

## Надёжность и границы

- Telegram update ID, заявки, статусы и whitelist operation ID фиксируются в БД. Доставка заявок, обращений и предложений идёт через транзакционный outbox: запись о доставке создаётся в одной транзакции с самим обращением, поэтому потерять её нельзя. Неудачные попытки повторяются с растущей задержкой (от 15 секунд до 6 часов), а событие, застрявшее в статусе `sending` дольше 5 минут (процесс убили посреди отправки), возвращается в очередь. Это семантика «как минимум один раз»: повтор сообщения возможен, потеря — нет. Пороговые уведомления устроены иначе: при явной ошибке Telegram событие помечается `failed` и не повторяется автоматически, потому что дубль легко принять за новое событие.
- Приём заявок защищён уникальным индексом активной заявки и атомарными статусными переходами.
- Whitelist не подтверждается пользователю до ответа Paper-плагина. При таймауте операция не переотправляется автоматически; повторное нажатие с тем же ключом безопасно.
- `STAFF` добавляет начальный roster только для отсутствующих в БД пользователей; дальнейшие изменения ролей хранятся в БД и переживают рестарт. Действующий владелец уровня 5 использует `назначитьадмина <Telegram ID> <1–5>` и `снятьадмина <Telegram ID>` в служебной группе. Уровни, которых нет в `config/levels.yml`, назначить нельзя.
- Бот не может модифицировать права участников анонимно без определения действующего Telegram-аккаунта. Сообщения от имени группы никогда не используются для определения действующего пользователя.
- Настройте регулярный резервный dump PostgreSQL/SQLite и TLS. Для Telegram бота используется long polling; webhook не включён.

## Проверки

`pytest` запускает автоматические unit-тесты. Telegram и Paper интеграции требуют тестовой супергруппы/сервера; перед боем проверьте права, темы, whitelist, повторные callback и отключение API.

## Подробная настройка Telegram

### 1. Создание бота

1. Откройте официальный `@BotFather`, выполните `/newbot`, задайте отображаемое имя и уникальный username.
2. Сохраните выданный Bot Token в `BOT_TOKEN` файла `.env`. Не отправляйте его в групповые чаты, не коммитьте `.env` и не помещайте секрет в YAML/исходники.
3. Через `/setjoingroups` разрешите добавление бота в группы. Через `/setprivacy` выберите `Disable`: иначе Telegram не будет присылать обычные сообщения из групп, необходимые для счётчика и текстовых команд. Бот не сохраняет сообщения, отправленные от имени группы/анонимных администраторов.
4. По желанию задайте короткое описание через `/setdescription`. Кнопки меню формируются ботом после `/start`.

### 2. Группы, темы и права

Создайте супергруппу сообщества и отдельные приватные супергруппы для заявок/поддержки/администрации (их можно объединить, если так удобнее). В настройках группы включите **Темы (Topics)** для каждого чата, в который бот отправляет заявки или обращения. Добавьте бота в нужные группы.

Для **чата заявок** выдайте боту права администратора:

- управлять темами (создать отдельную тему для заявки);
- отправлять сообщения и читать сообщения;
- при необходимости удалять/редактировать сообщения.

Для **чата поддержки/обращений/идей** нужны управление темами, отправка сообщений и чтение. Для **игровой группы**, где запускаются команды модерации, дополнительно выдайте `Блокировать пользователей` и `Ограничивать участников`. Не выдавайте лишних прав. Бот не назначает Telegram-администраторов.

Скопируйте ID супергрупп в переменные `APPLICATIONS_CHAT_ID`, `SUPPORT_CHAT_ID`, `SUGGESTIONS_CHAT_ID`, `ADMIN_CHAT_ID`. ID обычно отрицательный (`-100…`). Для ID чата запустите `/chatid` (в личке — свой chat ID, в группе — только администратор с правом `settings`). Стороннему боту для получения ID не передавайте секреты и токен Mellow. Команда `/id` в личном диалоге показывает ID только самому вызвавшему пользователю, в группах она ничего не раскрывает.

После настройки запустите бота и проверьте в тестовой группе: `/start` в личном диалоге, создание тестовой заявки, появление отдельной темы и доступность кнопок. Если Telegram отвечает `CHAT_NOT_FOUND` или `not enough rights`, проверьте ID и права бота.

### 3. Администрация и права

Используйте отдельный приватный супергрупповой чат. Членство в нём должно быть ограничено персоналом. Для форумной обработки обращений включите темы и выдайте боту управление ими и отправку сообщений. В `.env` первоначальный набор указывается как `STAFF=123456789:5,987654321:2`; каждый человек может узнать собственный ID командой `/id` в личке бота. Не публикуйте список ID в общедоступном чате.

Права и названия уровней редактируются в `config/levels.yml`; проверки выполняются на сервере при каждом действии. Владельцы уровня 5 могут назначать уровень и снимать права сообщениями `назначитьадмина <Telegram ID> <уровень 1–5>` и `снятьадмина <Telegram ID>` в служебной группе. Нельзя менять собственную роль; более низкий уровень не может менять роль равного/старшего. Изменения сохраняются в БД и не стираются при рестарте. Конфигурация `STAFF` используется как начальное заполнение пустого roster.

Для обработки анонимных сообщений от имени группы личность автора никогда не нужна и не извлекается. Действия, сделанные кнопкой в групповом чате, проверяются по текущему Telegram callback-пользователю, но его ID намеренно не записывается в аудит/поле проверяющего; такие записи имеют `actor_id = NULL`. Чтобы анонимный участник не мог выполнять модерационные текстовые команды, сообщения с `sender_chat` для команд игнорируются.

Проверяйте не на боевой группе, а на тестовой супергруппе: заявку и повторный submit, кнопки принятия/отклонения/запроса данных, права второго уровня, команды модерации с ID и reply, обычные и анонимные сообщения, команду `статистика` в группе и в личке, переход 99→100, успешный/повторный whitelist и отказ при выключенном API.
